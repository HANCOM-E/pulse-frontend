# 감정 태깅 정확도 검증 (τ 확정)

- 대상: `lib/tagger/tagger.js` — KoELECTRA-small-v3 NSMC 파인튜닝 모델(ONNX int8) + τ 마진 밴드
- 모델 버전: `koelectra-small-v3-nsmc-q8+tau-1.2`
- 검증일: 2026-08-14
- 담당: 한윤지 (축 2 · 참가자 입력 + 감정 태깅)

---

## 1. 왜 τ가 필요한가

NSMC로 학습된 원본 모델은 **긍정/부정 2진 분류기**입니다. 그런데 Pulse는 중립(NEU)이 필요합니다.
"자료 공유는 어디서 받나요" 같은 질문에 억지로 POS/NEG를 붙이면 대시보드 감정 분포가 왜곡됩니다.

그래서 두 로짓의 차이를 마진으로 쓰고, 마진이 작으면 판단을 유보합니다.

```text
margin = logit_pos - logit_neg
|margin| < τ  →  NEU
margin > 0    →  POS
margin < 0    →  NEG
```

소프트맥스를 쓰지 않은 이유: 2진 소프트맥스는 확률이 0/1로 몰려서(포화) 애매한 문장과 확실한 문장이 구분되지 않습니다. 로짓 차이가 애매함의 크기를 더 잘 보존합니다.

**τ가 클수록 NEU 판정이 늘어납니다.** 이 값을 데이터로 정하는 것이 이 문서의 목적입니다.

---

## 2. 평가 데이터

실제 행사 소감을 흉내 낸 한국어 문장 182개를 직접 작성하고 라벨링했습니다.

평가 문장은 `docs/tagger-eval/`에 함께 커밋했습니다. `문장\t라벨` 형식의 TSV입니다.

| 용도              | 파일                                |    건수 |    POS |    NEU |    NEG |
| ----------------- | ----------------------------------- | ------: | -----: | -----: | -----: |
| 튜닝              | `docs/tagger-eval/tuning-base.txt`  |     102 |     34 |     22 |     46 |
| 튜닝              | `docs/tagger-eval/tuning-add.txt`   |      20 |      8 |     12 |      0 |
| **튜닝 합계**     |                                     | **122** | **42** | **34** | **46** |
| 홀드아웃          | `docs/tagger-eval/holdout-base.txt` |      50 |     13 |     12 |     25 |
| 홀드아웃          | `docs/tagger-eval/holdout-add.txt`  |      10 |      4 |      6 |      0 |
| **홀드아웃 합계** |                                     |  **60** | **17** | **18** | **25** |

`add` 파일은 1차 작성 후 클래스 균형을 맞추려고 덧붙인 분량입니다. 아래 「클래스 균형」 참고.

**튜닝셋과 홀드아웃은 끝까지 분리했습니다.** τ는 튜닝셋으로만 골랐습니다. 홀드아웃은 τ를 `1.2`로 확정한 **뒤에** 처음 열었고, 결과를 보고 값을 되돌리지 않았습니다. 같은 데이터로 고르고 같은 데이터로 보고하면 성능이 실제보다 좋아 보입니다.

### 라벨링 기준

- **마지막 절이 결론입니다.** `~는데`/`~지만` 뒤에 오는 절을 따릅니다. NSMC로 학습된 모델이 한국어를 그렇게 읽기 때문입니다.
  - `설명은 좋았는데 예제가 부족했어요` → **NEG**
  - `초반 30분은 아까웠지만 나머지는 좋았어요` → **POS**
- **NEU는 감정이 없을 때만 씁니다.** 질문, 사실 진술, 판단 유보.
  - `발표 자료는 언제쯤 공유되나요` → NEU
  - `40분 정도 걸렸습니다` → NEU
- **욕설은 감정 라벨과 무관합니다.** `toxic`은 사전으로 판정하는 별개 불리언입니다.
  - `개같이 어려웠지만 배운 건 있습니다` → POS + toxic

### 클래스 균형

1차 작성 때 NEG 71 / POS 47 / NEU 34로 NEU가 부족했습니다. 클래스당 40개 기준을 맞추려고 NEU·POS 문장 30개를 추가했습니다. macro F1을 쓰는 이유도 같습니다 — 정확도는 다수 클래스만 맞혀도 높게 나옵니다.

## 3. τ 스윕 (튜닝셋 122건)

0부터 4까지 0.05 간격으로 훑고, 주요 지점을 읽었습니다.

|        τ |  macro F1 |                    |
| -------: | --------: | ------------------ |
|     0.75 |     0.713 | 기존 자리표시자 값 |
|     1.00 |     0.733 |                    |
| **1.20** | **0.724** | **채택**           |
|     1.35 |     0.733 | 스윕 최고점        |
|     1.50 |     0.725 |                    |
|     1.70 |     0.716 |                    |
|     2.00 |     0.716 |                    |

### 최고점(1.35)을 쓰지 않은 이유

**최고점이 표본에 따라 심하게 움직였습니다.**

| 표본                  | 최적 τ | macro F1 |
| --------------------- | -----: | -------: |
| 114건 (일부 누락)     |   0.75 |    0.724 |
| 134건 (홀드아웃 혼입) |   1.70 |    0.728 |
| 122건 (정상)          |   1.35 |    0.733 |

문장 몇 개 차이로 최적점이 두 배 넘게 이동하는데 macro F1은 0.01도 안 움직입니다. **최고점의 위치가 신호가 아니라 잡음이라는 뜻입니다.**

실제로 `1.00`–`1.50` 구간의 F1 폭은 `0.009`입니다. 122건에서 문장 하나가 다른 클래스로 넘어가면 macro F1이 약 `0.005` 움직이므로, 이 폭은 **문장 1–2개**에 해당합니다. 네 지점 모두 사실상 동률입니다.

그래서 최고점 대신 **동률 구간 안쪽의 값**을 골랐습니다. `1.2`는 왼쪽 급락 지점(`0.75`, F1 `0.713`)에서 충분히 떨어져 있고, 오른쪽 내리막이 시작되는 `1.70` 쪽으로도 여유가 있습니다.

구간의 산술 중앙은 `1.25`지만 그 값을 고집하지 않았습니다. **구간 안이면 어디를 골라도 차이가 문장 1–2개 수준**이라, 소수 둘째 자리를 쓸 근거가 없다고 봤습니다.

## 4. 최종 성능 (홀드아웃 60건, τ = 1.20)

**macro F1 = 0.736**

### 혼동행렬

| 정답 \ 예측 |    POS |   NEU |    NEG |  계 |
| ----------- | -----: | ----: | -----: | --: |
| **POS**     | **16** |     0 |      1 |  17 |
| **NEU**     |      4 | **9** |      5 |  18 |
| **NEG**     |      4 |     1 | **20** |  25 |
| 계          |     24 |    10 |     26 |  60 |

### 클래스별

| 클래스    | 정밀도 | 재현율 |        F1 | 라벨 수 |
| --------- | -----: | -----: | --------: | ------: |
| POS       |  0.667 |  0.941 |     0.781 |      17 |
| NEU       |  0.900 |  0.500 |     0.643 |      18 |
| NEG       |  0.769 |  0.800 |     0.784 |      25 |
| **macro** |        |        | **0.736** |      60 |

### 해석

**홀드아웃(0.736)이 튜닝셋(0.724)보다 높습니다.** τ가 튜닝 데이터에 과하게 맞춰지지 않았다는 신호입니다.

**NEU 재현율이 0.500으로 가장 약합니다.** 라벨 NEU 18건 중 9건만 맞혔고 나머지는 POS 4 / NEG 5로 흩어졌습니다. 다만 **정밀도는 0.900**입니다 — NEU라고 부른 10건 중 9건이 실제 NEU였습니다.

즉 모델은 **중립을 남발하지 않고 확실할 때만 중립이라고 합니다.** 대시보드 용도로는 이 방향이 낫다고 판단했습니다. 감정 분포가 온통 중립으로 채워지면 주최자가 얻을 정보가 없습니다.

**정반대 오분류(POS↔NEG)는 5건, 8.3%입니다.** 화면에 가장 눈에 띄게 틀리는 오류 유형인데, 절반 이상의 오류는 중립 경계에서 발생하고 있습니다.

### 홀드아웃의 최적 τ(1.95)에 대하여

평가 도구는 입력을 받으면 그 데이터의 최적 τ를 자동으로 함께 표시합니다. 홀드아웃에서는 `1.95`(F1 `0.744`)가 나왔습니다.

**이 값은 사후 진단이며 τ 선택에 사용하지 않았습니다.** τ는 이미 튜닝셋만으로 `1.2`로 확정된 뒤였고, 이 숫자를 보고 되돌리지도 않았습니다. 홀드아웃으로 파라미터를 고르는 순간 홀드아웃이 아니게 되기 때문입니다.

차이도 `0.008`로 문장 1개 수준이라, 되돌릴 이유 자체가 없었습니다.

## 5. 알려진 한계

- **평가셋이 합성 데이터입니다.** 실제 참가자 소감을 구할 수 없어 직접 작성했습니다. 실제 입력은 오탈자·초성·이모지가 더 많을 것이고 성능은 이보다 낮게 나올 가능성이 큽니다.
- **라벨러가 1명입니다.** 특히 `~는데`/`~지만` 대조 문장은 사람마다 다르게 읽을 수 있습니다. 교차 검증을 못 했습니다.
- **층 2 규칙은 수사의문문을 잡지 못합니다.** `이걸 세션이라고 하는 건가요`(NEG, 튜닝셋 97번)는 **형태가 질문이 맞아서** 규칙이 NEU로 확정합니다. 수사의문문은 모양이 아니라 의도로 갈리는데, 어미 규칙은 의도를 모릅니다. 평가셋 182건 중 1건이라 그대로 둡니다.

  > 이 문서 초판에서는 홀드아웃의 `NEG → NEU` 1건을 `이게 맞나 싶었습니다`가 의문 종결로 잡힌 것으로 적었으나 **오진이었습니다.** 그 문장은 `싶었습니다`로 끝나 규칙에 걸리지 않습니다. 실제 원인은 `끝나고 나니 뭘 들었는지 기억이 안 나요`였고, `-나요`가 의문 종결 어미와 동사 `나다`의 평서 종결을 동시에 가리키기 때문이었습니다. #165에서 고쳤습니다.

- **`toxic` 사전에 누락이 있습니다.** 튜닝셋 욕설 3건 중 2건만 잡혔습니다. 원인은 `개같-` 계열이 사전에 없는 것 하나였습니다(`개새`는 있지만 `개같`은 없습니다). `ㅅㅂ` 초성은 정상 동작합니다. 홀드아웃은 1건 중 1건 정상입니다. **τ와 무관합니다** — 사전·정규식 기반이라 모델과 독립입니다. 별도 이슈로 넘깁니다.
- **`UNKNOWN`은 집계에서 제외했습니다.** 모델 로딩 실패·타임아웃으로 태깅을 못 한 경우이며, 분류 성능이 아니라 가용성 문제입니다.
